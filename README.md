# 电子书校对

本地优先的中文小说智能拆章与批量校对工作台。

给它一个抓下来的 TXT，它会按章节规则智能拆分，让你选择要校对的章节范围，按可编辑的校对规则分批并发处理，实时显示进度，完成后自动合并导出干净的 TXT 和处理报告。

模型默认连接本机 **FreeLLMAPI**（`http://127.0.0.1:3001/v1`，模型 `auto`），也可以换成任意 OpenAI Chat Completions 兼容接口，包括 Ollama、OpenAI、DeepSeek、硅基流动、OpenRouter 等。

> 关于“开源方案调研与选型”的完整记录见 [`docs/OPEN_SOURCE_REVIEW.md`](docs/OPEN_SOURCE_REVIEW.md)。

## 为什么做这个

抓下来的网文 TXT 通常混合了多种问题：

- 排版错误：段落缩进、空行、引号、标点、断行不统一；
- 拼音输入错误和形近字：`童孔` → `瞳孔`、`勐的` → `猛地`、`前途无亮` → `前途无量`；
- 抓取噪声：`本章未完，点击下一页继续阅读`、`手机站全新改版升级地址`、站长请假说明、章节导航长行；
- 重复章节标题：抓取分页导致同一个 `第N章 标题` 出现多次；
- 章节号异常：倒序标题、误标章节号、跨章节号跳变，甚至混入另一本书的目录片段；
- 简繁混排：后段章节可能是繁体或台湾用词。

这个工作台把这些问题拆成两阶段处理：先用确定性规则做高置信清理，再让模型做保守的语义校对。

## 核心功能

- **智能拆章**：兼容中文数字、全角数字和阿拉伯数字标题（`第240章`、`第二百四十章`、`第２４０章`），合并连续重复标题，识别倒序标题与异常跳号。
- **范围选择**：任意起始章节与结束章节，界面实时显示预计处理章节数和字符数。
- **规则面板**：可编辑校对规则，随每个批次发送给模型；内置一套保守的推荐规则，可随时恢复。
- **批次与并发**：可配置每批章节数、并发批次数、单批字符安全上限；界面实时显示“最多在途章节数”。
- **模型可切换**：默认 FreeLLMAPI，也支持任意 OpenAI 兼容端点；内置连接测试。
- **模型配置本地保存**：可手动保存地址、模型、密钥和启动脚本路径，下次打开同一浏览器自动载入；也可清除已保存配置。
- **FreeLLM 启动器**：工作台内可直接调用 FreeLLMAPI 的 VBS 启动脚本；项目 `assets/` 中也保留了一份副本。
- **进度可视化**：进度环、进度条、并发通道状态、实时日志。
- **章节对比**：处理过程中即可查看已完成章节，逐处高亮删除与新增内容，并比较正文字符数；模型失败时标明规则回退。校对前内容为拆章结果，拆章前清除的已知混入内容不包含在对比中。
- **任务控制**：暂停、继续、取消。
- **失败保护**：模型缺章或明显截断会被拒绝；批量失败自动降为逐章重试。可选择失败后保留规则清理版，或不导出并等待重试；任务结束后可一键重试全部失败章节。
- **统一请求调度**：跨任务共享的全局并发闸门、动态升降并发、指数退避加随机抖动、遵守 Retry-After、错误分类重试，详见下文。
- **模型链自动切换**：模型框可填多个模型（英文逗号分隔），按限流与上游故障自动切换。
- **三级自动补偿**：主流程与重试轮都失败的章节进入 5 分钟 / 30 分钟 / 2 小时补偿队列，成功后自动替换规则回退版并更新导出。
- **任务记忆**：任务进度实时持久化，重启工作台后自动载入未完成任务，重新导入原稿即可继续。
- **自动导出**：完成后按章节号自动合并，导出 TXT 与 JSON 报告，写入 `exports/`。
- **不覆盖源文件**：源 TXT 只读导入，结果写入独立目录。

## 快速开始

### 方式一：双击启动（Windows）

双击：

```text
电子书校对.vbs
```

然后浏览器会打开：

```text
http://127.0.0.1:3210
```

### 方式二：命令行启动

```bash
node server.js
```

要求 **Node.js 22+**。项目没有外部 npm 依赖。

## 使用流程

1. 导入 TXT 小说文件。
2. 等待拆章分析，查看章节数、平均长度、重复标题、缺失章节号与解析提醒。
3. 设置起始章节和结束章节。
4. 在“模型连接”中保留 FreeLLMAPI，或填写其他 OpenAI 兼容接口。
5. 若 FreeLLMAPI 未运行，点击“启动 FreeLLMAPI”。默认调用：

   ```text
   用户桌面\FreeLLMAPI 启动器.vbs
   ```

   也可以把该脚本换成你自己的路径。
6. 从 FreeLLMAPI 仪表盘复制统一密钥，填入 API Key 后点“测试连接”。
7. 编辑校对规则、每批章节数、并发数、单批字符上限。
8. 点击“开始校对并自动导出”。
9. 在“处理进度”的“章节对比”中，点击已完成的章节，查看校对前后的标题和正文。红色删除线表示删除，绿色表示新增；模型校对失败的章节标记为“规则回退”。
10. 完成后下载合并 TXT 和 JSON 报告。

“模型校对失败时使用规则清理版”默认开启。关闭后，如果章节仍失败，任务不会生成不完整的合并导出；可调整模型连接或校对规则，点击“一键重试失败章节”。开启时会先导出包含回退章节的版本，重试成功后重新导出；此前生成的文件会保留。重试只处理失败章节，不会重新处理成功章节。

章节正文字符数按 Unicode 字符统计，包含空格和换行，不包含标题。校对前内容是拆章后的原文；拆章之前已移除的已知混入内容不会出现在对比中。对比覆盖规则清理和模型校对的综合结果。极长或变化很大的片段可能整段高亮，仍可查看完整内容。

章节对比和任务状态默认保存在当前服务进程内；同时每个任务的进度会实时持久化到 `.jobs/`，重启工作台后自动载入未完成任务，重新导入原稿即可从断点继续。导出的 TXT 和报告仍保存在 `exports/`。

## 统一请求调度与可靠性

免费模型池（FreeLLMAPI 等）的典型故障是限流、上游超时和间歇性 5xx。工作台在“批量失败 → 逐章重试 → 规则回退”之前加了一层统一请求调度器（`core/request-scheduler.js`）：

- **全局并发闸门**：所有任务共享一个在途请求上限（默认 8）。即使同时跑多个任务、每个任务并发调到 10，实际到达模型的请求也不会超过全局上限。
- **动态并发**：初始 3，连续成功逐步升到 10；连续遇到 429 自动降档，最低 1。
- **指数退避 + 随机抖动**：重试基础等待 2 秒、4 秒……再加随机偏移；上游返回 `Retry-After` 或响应体 `retryAtMs` 时优先遵守（上限 60 秒）。
- **错误分类**：429 / 502 / 503 / 504 / 408 / 网络失败 / 模型输出缺章或截断，按退避重试；401 / 403 / 400 / 404 视为配置问题，立即停止同配置重试。
- **模型链**：模型框支持逗号分隔多个模型（如 `deepseek-v4-flash, glm-4.7-flash, qwen3.7-flash`），遇到限流或上游故障自动切换到下一个。
- **路由与成功率**：`GET /api/scheduler` 与界面“请求调度”面板实时显示在途数、动态并发、成功率、各模型成功/失败统计与最近请求明细。
- **三级自动补偿**：主流程 + 逐章重试轮 + 自动重试轮都失败的章节进入补偿队列——5 分钟第 1 次、30 分钟第 2 次、2 小时第 3 次；补偿成功立即替换规则回退版并刷新导出，三次都失败则保留并标记，可手动重试。

这些行为都可以用环境变量覆盖（测试用）：`SCHEDULER_MAX_GLOBAL`、`SCHEDULER_INITIAL_CONCURRENCY`、`SCHEDULER_MAX_CONCURRENCY`、`SCHEDULER_BACKOFF_BASE_MS`、`SCHEDULER_MAX_ATTEMPTS`、`COMPENSATION_DELAYS_MS`、`COMPENSATION_TICK_MS`。

## 默认批次建议

基于《百世飞升》真实文件实测：单章平均约 **4,357 字符**。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 每批章节数 | `3` | 约 13,000 字符输入，模型还要输出接近等长的正文 |
| 并发批次 | `2` | 与常见开源小说工具默认并发一致 |
| 单批字符上限 | `18,000` | 超过时自动提前切批 |
| 最多在途章节 | `6` | 3 × 2 |

FreeLLMAPI 免费模型池实测：单批 3 章（约 14,000 字符）容易触发其内部 45 秒首字节预算而整体超时；**每批 1-2 章、单批字符上限 12,000 左右成功率更高**，失败章节会被自动降级逐章重试，不必手动干预。

不建议直接开到“每批 5 章 + 并发 10 批”。那样相当于约 50 章同时处理，FreeLLMAPI 免费模型池更容易出现限流、超时、上下文超限或输出截断。调度器的全局闸门会在这种配置下自动收敛实际并发。

如果你用的是付费大模型且上下文很长，可以把每批章节数调到 `5`、并发调到 `3-4`，界面会实时提示估算负载。

## 两种处理模式

- **模型智能校对**：先跑高置信规则清理，再调用模型处理错字、拼音输入错误和上下文相关问题。
- **仅规则整理**：完全离线，不调用模型，适合先做拆章、重复标题合并、抓取噪声清理和排版统一。

## 世界观词表（专名保护）

批量校对最大的风险之一，是模型把只出现一两次的人名、功法、法宝、地名当成错别字“改正常见词”。工作台因此内置了**世界观词表**：

- **手动维护**：直接在词表面板编辑 JSON，字段为 `name / type / aliases / note`。
- **自动提取**：选择章节范围后点“自动提取词表”，服务端会聚合较多章节（默认上限 120,000 字符，均匀抽样最多 40 章）一次性交给模型抽取人名、称谓、功法、法宝、地点、势力与术语，并合并进现有词表。
- **注入校对**：每个批次都会把词表压缩成“必须原样保留”的提示词段落一起发送；正文写法与词表不一致时以词表为准。
- **自升级反馈（扩展功能，默认关闭）**：开启后，模型在批次中新发现的关键专名会自动写入词表，并记录来源章节，日志和报告都会列出新增项；后续批次立即复用。
- **联网增强（可选）**：提取时勾选后，会在提示词中要求模型对低置信条目做外部核对；若端点本身不支持联网或搜索工具，该选项只会强化“不要臆造”的约束。

建议流程：

1. 先用**更强的模型和更大的上下文**跑一次词表提取；
2. 人工过一遍词表，删掉误收条目；
3. 再按较小批次做全书校对。

## 模型服务商与模型列表

内置预设：FreeLLMAPI、Ollama、OpenAI、DeepSeek、月之暗面 Kimi、智谱 GLM、硅基流动、阿里云百炼、火山方舟、OpenRouter、Groq、自定义。

- 选中预设会自动填入 Base URL 与默认模型；
- “拉取模型列表”会调用对应端点的 `/models`，把返回的模型 id 填入模型输入框的下拉建议；
- 任意 OpenAI Chat Completions 兼容端点都可以用“自定义”直接填写。

## 规则引擎做了什么

`core/novel-core.js` 中的确定性规则：

- 章节标题识别与编号规范化；
- 连续重复标题合并；
- 倒序标题识别，并结合后续编号判断是否属于误标；
- 远距离跳号按“异书混入或目录噪声”忽略，并跳过污染区间，避免把别的书正文并入当前章节；
- 抓取噪声整行删除与行内删除；
- 被翻页提示截断的句子重新拼接；
- 高置信错字、词形和重复标点修正；
- 英文省略号统一为中文省略号，段落缩进统一。

这些规则都有测试覆盖，见 `tests/novel-core.test.js`。

## 项目结构

```text
电子书校对/
├─ server.js                   本机 HTTP 服务与任务调度
├─ core/novel-core.js          拆章、清理、合并核心
├─ core/request-scheduler.js   统一请求调度（并发闸门、退避、错误分类、统计）
├─ core/provider-presets.json  服务商预设与提取建议
├─ core/default-glossary.json  默认世界观词表
├─ public/                     工作台前端
│  ├─ index.html
│  ├─ styles.css
│  ├─ app.js
│  └─ diff.js                  章节差异对比
├─ scripts/
│  ├─ prepare-book.js          命令行整理与报告生成
│  └─ smoke-test.js            端到端冒烟测试
├─ tests/                      核心规则、调度与任务恢复测试
├─ .jobs/                      未完成任务进度快照（不进仓库）
├─ glossaries/                 词表存档（不进仓库）
├─ assets/                     FreeLLMAPI 启动脚本副本
└─ 电子书校对.vbs              双击启动入口
```

导出目录：

```text
电子书校对/exports/
```

## 命令行整理

不使用界面，也可以直接生成整理版和报告：

```bash
node scripts/prepare-book.js \
  --input "你的小说.txt" \
  --output "整理版.txt" \
  --report "整理报告.txt" \
  --json "分析明细.json" \
  --start 240
```

## 测试

```bash
node --test tests/*.test.js
node scripts/smoke-test.js "你的小说.txt"           # 规则模式端到端
node scripts/smoke-test-glossary.js "你的小说.txt" # 词表保存、读取与模型任务回退
```

后两个脚本需要先启动工作台（`node server.js`），会用真实文件完成一次拆章分析和小范围任务，并校验自动导出结果。

## 安全与隐私

- 源 TXT 只读导入，不会被覆盖。
- API Key 默认仅存在于当前页面和当前任务对象内，不写入项目配置文件，也不进入仓库。选择“保存模型配置到本机”后，密钥会以明文存储在当前浏览器的本地存储中，使用此浏览器的其他人可能读取；请勿在公用电脑上保存，可随时清除。
- 静态文件服务限制在项目 `public/` 目录内。
- 外部模型请求只发往你填写的 Base URL。
